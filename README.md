# au-core-tests (Test IG sketch)

A minimal proof-of-concept: fhir-frog's AU Core TestScripts, packaged as
their own FHIR Implementation Guide that depends on `hl7.fhir.au.core`
without modifying it - a "Test IG", as opposed to a fork or extension of
AU Core itself. Several such Test IGs could exist against the same AU Core
version (this repo's own, a vendor's, a jurisdiction's) with no
coordination between them required.

This directly answers a limitation of Inferno's approach: an AU Core test
kit there is a separate Ruby gem with its own bespoke packaging - it can't
be resolved as a FHIR dependency by canonical URL/version the way any other
IG can. Because fhir-frog TestScripts are themselves valid FHIR resources,
they can be distributed exactly like any other IG's content.

## What this proves

- `sushi .` compiles cleanly (0 errors) with `hl7.fhir.au.core#2.0.0`
  declared as a real dependency, resolved from the local package cache.
- All 37 resources (14 TestScripts + 23 fixtures, synced by
  `sync-resources.py`) under `input/resources/` are listed as the IG's own
  resources in the generated `ImplementationGuide-fhirfrog.au-core-tests.json`.
- `fhir-frog`'s existing `IgPackageLoader` (which already resolves a
  package plus its full transitive dependency closure via
  `FilesystemPackageCacheManager`) needs no changes to resolve a Test IG
  shaped like this one - the same "id#version" + dependency-closure
  resolution already built for AU Core itself applies unchanged.
- `../../testscripts/` stays the single source of truth -
  `input/resources/` is entirely generated by `sync-resources.py`, not
  hand-maintained. Re-run it after any change there.
- The fixtures genuinely conform to the AU Core profiles they're implicit
  examples of, checked end-to-end through `fhir-frog`'s own
  `TestScriptEngine`/`ProfileValidator`/`IgPackageLoader` chain (a
  fixture-sourced `validateProfileId` assert, `igPackage:
  "hl7.fhir.au.core#2.0.0"`, no server needed): `Patient-au-core-patient-conformant`,
  `Condition-au-core-condition-conformant`, and
  `AllergyIntolerance-au-core-allergyintolerance-conformant` all PASS
  against their respective `au-core-*` StructureDefinitions.

## What this is *not* (yet)

- No IG Publisher build attempted - this is SUSHI-compile-only, matching
  the scope decision made for `fhir-frog-library`'s own `frog-test-plan`
  profile work (compiled resources, no hosted/rendered IG site).
- Fixtures are packaged as plain resources (each gets a synthesized `id`
  from its filename if it didn't already have one - needed since IG
  Publisher addresses every resource as `<ResourceType>/<id>`), **not**
  as IG Publisher "Example of `<profile>`" - most have no `meta.profile`
  today, and adding one would be a conformance-semantics change to files
  `TestScriptEngine` actively loads at runtime, not just a packaging
  decision. Worth revisiting once an actual IG Publisher build is
  attempted and "Example of" categorization is wanted for real.
- This Test IG isn't yet installed into any package cache/registry - it's
  only compiled locally. `frog-runner` *can* now consume a package shaped
  like this one (its `RunService` resolves a `testPackage` via
  `fhir-frog-library`'s new `TestPackageResolver`, sorting a package's
  flat resource folder into TestScripts-at-top-level +
  everything-else-under-`fixtures/`, then runs it through the exact same
  discovery/execution path as a flat `bundlePath` - see frog-runner's own
  README), but there's no `fhirfrog.au-core-tests#0.1.0` sitting in any
  cache for it to actually resolve yet. Getting this Test IG installed
  somewhere `FilesystemPackageCacheManager` can find it (a local `sushi
  build` + manual cache placement, or a real package registry) is the
  remaining step to close the loop end-to-end.

## Build

```
python3 sync-resources.py   # regenerate input/resources/ from ../../testscripts/
sushi .
```
